# Отчёт об оптимизации AgriSense

**Дата:** 16 сентября 2026  
**Ветка:** `optimize-io`  
**Объём изменений:** 5 файлов исходного кода, ~150 строк

---

## 1. Где было узкое место

Замеры показали, что время любого анализа определяется сетевым вводом-выводом
к Microsoft Planetary Computer, а не вычислениями на GPU. Найдены четыре причины
лишнего трафика:

- Клиент STAC создавался заново при каждом поиске сцены: для временного ряда из
  семи окон это четырнадцать обращений к каталогу вместо семи.
- Одни и те же каналы Sentinel-2 скачивались повторно. «Спутниковый снимок»
  читает B02/B03/B04, NDVI читает те же три канала плюс B8A, загрузка области в
  SAM — снова те же три.
- Снимки читались в полном разрешении 10 м, около 1700×1400 пикселей на канал.
  SAM внутри себя всё равно сжимает изображение до 1024 пикселей, а наложение на
  карту от лишних пикселей ничего не выигрывает.
- Детекция изменений скачивала четыре канала, а использовала два.

Дополнительно: словари задач и чат-сессий росли неограниченно, версии
torch и torchvision в Dockerfile не были зафиксированы вопреки комментарию о
воспроизводимости сборки, у сервиса приложения отсутствовала проверка
работоспособности, а объявленная блокировка GPU нигде не использовалась.

## 2. Что сделано

1. **Кэш клиента STAC и мемоизация поиска сцен.** Один подписанный клиент на
   процесс, результаты поиска живут 30 минут (подписанные ссылки действуют около
   часа).
2. **LRU-кэш прочитанных каналов** по ключу «сцена, канал, область, размер».
   Инструменты переиспользуют одну загрузку вместо повторной.
3. **Ограничение разрешения чтения** 1024 пикселями по длинной стороне. Rasterio
   берёт данные из пирамид COG, а не скачивает все тайлы. Отключается
   переменной `AGRISENSE_MAX_PX=0`.
4. **Детекция изменений запрашивает только красный и ближний ИК** вместо всех
   четырёх каналов.
5. **Ограничены реестры задач и чат-сессий** (по 64 записи).
6. **Инфраструктура.** Зафиксированы версии torch 2.11.0 и torchvision 0.26.0;
   добавлена проверка работоспособности сервиса приложения, без которой
   `docker compose up --wait` завершался раньше, чем приложение начинало отвечать;
   устранена гонка в SAM между фоновым кодированием снимка и предсказанием по
   клику пользователя.
7. **Добавлен скрипт `bench.py`** для воспроизведения измерений.

## 3. Результаты измерений

Область Костанай (17×14 км), медиана трёх запусков, кэш очищается перед каждым
запуском.

| Операция | До | После | Выигрыш |
|---|---|---|---|
| Спутниковый снимок | 8.2 с | 5.5 с | −33% |
| NDVI | 7.8 с | 6.6 с | −16% |
| Временной ряд NDVI, 7 месяцев | 12.5 с | 10.1 с | −19% |
| Детекция изменений, 2 года | 14.5 с | 8.8 с | −39% |

Сценарий работы пользователя с одним участком: снимок, затем NDVI, затем
повторный снимок.

| Шаг | До | После |
|---|---|---|
| Снимок | 8.0 с | 5.5 с |
| NDVI | 9.3 с | 1.9 с |
| Снимок повторно | 5.8 с | 0.5 с |
| **Итого** | **23.1 с** | **7.9 с** (−66%) |

Объём переданных данных:

| Показатель | До | После |
|---|---|---|
| Прочитано пикселей, снимок | 7.4 Мпикс | 2.7 Мпикс |
| Прочитано пикселей, детекция изменений | 19.7 Мпикс | 3.6 Мпикс |
| Размер наложения, снимок | 7.0 МБ | 2.5 МБ |
| Размер наложения, NDVI | 3.2 МБ | 1.2 МБ |

Сокращение размера наложений особенно заметно при работе через проброс порта
VS Code Remote-SSH, где именно эти мегабайты определяли скорость отрисовки карты.

## 4. Проверка корректности

**Модульные проверки, 15 из 15 пройдены.** Мемоизация возвращает тот же объект
сцены; чтение ограничивается ровно 1024 пикселями; все каналы лежат на одной
сетке; NDVI остаётся в диапазоне от −1 до 1; NDVI, посчитанный по сокращённому
набору каналов, **численно совпадает** с NDVI по полному набору, то есть
оптимизация детекции изменений не меняет результат.

**Сквозные проверки против запущенного сервера, 15 из 15 пройдены.** Все
эндпоинты анализа отвечают, экспорт GeoTIFF отдаёт корректный файл, слишком
большая область отклоняется кодом 400, предварительный прогрев пресетов при
старте проходит без единой трассировки ошибки. Команда проверки
работоспособности из docker-compose выполнена внутри контейнера с кодом 0.

## 5. Компромисс

Ограничение разрешения распространяется и на экспорт GeoTIFF: для крупного
участка файл получается около 15 м на пиксель вместо 10 м. Полное разрешение
возвращается переменной окружения `AGRISENSE_MAX_PX=0`, промежуточные значения
позволяют выбрать баланс между размером выгрузки и детальностью.
